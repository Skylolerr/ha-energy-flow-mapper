# HA checks, coverage, suggestions and image export – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show HA's energy validation at the blocks, the share of home consumption covered by devices, child-device suggestions with a stored ignore list, and a PNG export of the whole diagram.

**Architecture:** Backend: pure functions in `hierarchy.py` (mapping, filters, child pairs), one HA call in `energy_access.py`, registry reading in `candidates.py`, a new small store `suggestions.py`, new fields in `get`/`card` and two admin commands in `websocket.py`. Panel: pure helpers in `draft.ts` and a new `export.ts`; UI in the panel and card.

**Tech Stack:** Python (HA custom integration; tests with `pytest-homeassistant` on 2026.11 and `pytest-homeassistant-custom-component` on 2026.10 via `tests/common.py`), TypeScript + Lit (vitest, happy-dom, rollup).

**Spec:** `docs/superpowers/specs/2026-11-06-insights-design.md` (approved 2026-11-06). `SPEC.md` stays binding.

## Global Constraints

- Minimum Home Assistant stays **2026.10.0**; every task works on 2026.10.0 and 2026.11.0 (both CI jobs).
- No entities, no devices; the backup store format is unchanged (no `STORAGE_VERSION` bump).
- New store: key `energy_flow_mapper.suggestions`, version 1, content `{"ignored": [{"kind", "stat", "parent"}]}`.
- Every new WebSocket command is admin-only. The card command stays readable by all users and never returns prices or costs.
- Suggestions come only from `parent_device_id` (child devices), never from `via_device_id`.
- Nothing changes energy settings except saving a draft.
- Every new user-facing string in EN, DE, FR, IT in the same task; backend exceptions also in `strings.json` + `translations/*.json`.
- Panel bundle rebuilt and committed with every panel task (`cd panel && npm run build`).
- Windows test command: `.venv/Scripts/python.exe -m pytest -p win_ha_test_shim`; the 2026.11 venv in the session scratchpad (`tv`) is run the same way.
- No release; CHANGELOG gets an `[Unreleased]` section only.

## Review Focus

1. **An HA issue for a source whose statistic is also a device** (configuration error the user is fixing): mapping must not crash or attach it twice → test in Task 2.
2. **HA validation raising** (recorder not ready at startup): `get` and `card` still answer, with no HA messages → test in Task 3.
3. **A child device whose parent has the parent stat in the other list** (electricity child, water parent): no suggestion → test in Task 1.
4. **Export with names hidden but a device whose name equals its area or contains the entity ID**: none of the name, area, stat or entity ID text appears anywhere in the SVG (including `title`/`aria` attributes) → test in Task 10.
5. **Coverage when Home has a value of 0 or a negative untracked rest** (devices > home): no division by zero, "over 100 %" text → test in Task 7.

### Task 2: Map HA validation to blocks

**Files:**
- Modify: `custom_components/energy_flow_mapper/hierarchy.py`
- Test: `tests/test_hierarchy.py`

**Interfaces:**
- Consumes: `source_roles`, `source_kind`, `Issue`, `IssueCode`, `KEY_*` constants.
- Produces: `ha_issues(prefs: Prefs, validation: Mapping[str, Any], own: Sequence[Issue]) -> list[dict[str, Any]]` returning `{"stat", "kind", "type", "placeholders", "entities": [[entity, detail], ...]}`. Input `validation` is HA's `as_dict()` shape with lists instead of sets (`{"energy_sources": [[{type, affected_entities, translation_placeholders}]], "device_consumption": [...], "device_consumption_water": [...]}`), indexed like the saved prefs.
  Mapping: device entry → its `stat_consumption`; source entry → the block statistic equal to the affected entity, else the source's first block statistic (`source_roles` order); entries beyond the list length are dropped. Overlap filter: drop an `(stat, type)` whose affected entity is `stat` when `own` has an issue on that stat with the matching code: `statistic_missing`↔`statistics_not_defined`, `not_energy_unit`↔`entity_unexpected_unit_energy`, `not_water_unit`↔`entity_unexpected_unit_water`.
- Produces: `PRICE_ISSUE_TYPES: Final = frozenset({"entity_unexpected_unit_energy_price", "entity_unexpected_unit_gas_price", "entity_unexpected_unit_water_price", "entity_gas_price_unit_mismatch"})` and `card_ha_issues(issues: Sequence[Mapping[str, Any]], allowed: set[str]) -> list[dict[str, Any]]` – drops price types, keeps only entities in `allowed`, drops entries left without entities.

- [ ] **Step 1: Failing tests** `test_ha_issues_device_by_index`, `test_ha_issues_grid_export_entity_goes_to_export_block`, `test_ha_issues_price_entity_goes_to_first_source_block`, `test_ha_issues_index_beyond_list_dropped`, `test_ha_issues_overlap_with_own_issue_dropped`, `test_ha_issues_stat_both_source_and_device` (Review Focus 1: one entry for the source block, one for the device, no exception), `test_card_ha_issues_allowlist_and_price_types`.
